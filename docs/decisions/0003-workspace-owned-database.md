# ADR 0003：主数据库位于用户选择的工作区

- 状态：Accepted
- 日期：2026-09-01

## 背景

题包、音频、图片、数据库与备份可能逐渐变大，用户也可能希望把学习资料放在非 C 盘、移动硬盘或单独的数据目录。若应用把主数据静默放入 AppData，用户难以理解、迁移和备份其数据，也可能快速占用系统盘。

## 决策

- 首次启动必须要求用户明确选择一个可写的学习工作区。
- `ielts-workbench.sqlite3`、题包、媒体、imports、themes、backups 与 logs 均位于该工作区。
- AppData 最多保存很小的 bootstrap 配置，例如上次选择的规范化工作区路径；不保存主数据库或大型内容。
- Rust 规范化选择路径、验证可写性并建立固定目录结构。
- 所有后续相对路径必须在规范化后仍位于工作区；拒绝绝对子路径、`..`、盘符前缀以及符号链接/重解析点越界。
- 切换工作区是显式操作。第一阶段可以只提供“重新选择”；未来迁移必须区分“仅切换”和“复制迁移”，并在破坏性迁移前备份。

## 结果

- 用户可以直观看到、备份和迁移完整学习数据，并自行选择磁盘。
- 应用不会把大型数据锁定在 C 盘或 AppData。
- 每条数据库/媒体命令都需要解析当前工作区和进行边界检查。
- 工作区不可用、只读、被移动或介质断开时，应用必须显示可恢复错误，不能静默创建另一个数据库。
- 移动盘上的性能和并发写入质量由介质决定；SQLite 仍需事务、外键和正确关闭连接。

## 未采用方案

- 固定使用 AppData：不满足数据可见性、磁盘选择和大文件边界。
- renderer 直接保存任意绝对路径：扩大权限，难以统一防止路径穿越。
- 浏览器 localStorage/IndexedDB 作为主存储：不满足可审计的工作区 SQLite、迁移与桌面数据管理要求。
